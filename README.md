# RilzzCam v1.0 — USB + Wi-Fi webcam streaming MVP

RilzzCam is a personal Android-to-Windows camera streaming project.
This first version sends JPEG frames from Android to a Windows receiver over TCP.

## What works in this MVP
- Android companion app using CameraX.
- Front/back camera switching.
- USB connection through `adb reverse`.
- Wi-Fi connection through the PC's local IP address.
- Windows receiver preview using OpenCV.

## Important limitation
This is the first streaming milestone, **not yet a system-wide virtual webcam driver**.
The Windows window displays the live camera. The next milestone can expose it to OBS/Zoom
through OBS Virtual Camera or a dedicated DirectShow virtual-camera component.

## Requirements
- Windows 10/11
- Android phone with Android 8.0+
- Android SDK (API 35 recommended), JDK 17, Gradle (wrapper can be generated by Android Studio)
- Python 3.10+
- USB debugging enabled for USB mode

## 1. Start Windows receiver
Open PowerShell in `windows`:

```powershell
py -m pip install -r requirements.txt
py rilzzcam_receiver.py
```

Allow Python through Windows Firewall on private networks if Windows asks.
The receiver listens on TCP port `4747`.

## 2. Build Android app
Open the `android` folder in Android Studio, or build from command line after installing
Android Gradle Plugin-compatible tooling:

```powershell
cd android
gradle assembleDebug
```

The APK is generated at:
`android/app/build/outputs/apk/debug/app-debug.apk`

Install it:
```powershell
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## 3. USB mode
Connect phone by USB, accept the USB debugging authorization prompt, then run:

```powershell
adb devices
adb reverse tcp:4747 tcp:4747
```

In RilzzCam Android, leave the host as `127.0.0.1`, port `4747`, then tap **Connect & Start**.

## 4. Wi-Fi mode
1. Connect phone and PC to the same Wi-Fi network.
2. Find the PC IPv4 address with `ipconfig`.
3. In the Android app, enter that IPv4 address, e.g. `192.168.1.10`.
4. Keep port `4747`, then tap **Connect & Start**.

For Wi-Fi, Windows Firewall must allow inbound TCP port 4747 on Private networks.

## Protocol
Each frame is:
- 4-byte unsigned big-endian JPEG length
- JPEG payload bytes

The receiver reads frames continuously and displays them in an OpenCV window.

## Troubleshooting
- `Connection refused`: start the Windows receiver first; check IP/port; for USB rerun `adb reverse`.
- USB device says `unauthorized`: unlock the phone and accept the RSA authorization prompt.
- No camera preview: grant camera permission to RilzzCam in Android settings.
- Wi-Fi does not connect: verify both devices are on the same LAN and allow port 4747 in Firewall.
- Lag: lower capture rate in `MainActivity.kt` by changing `FRAME_INTERVAL_MS` from `100L` to `150L` or `200L`.

## Build Android APK with GitHub (without Android Studio on your PC)

1. Create a new empty repository on GitHub, for example `RilzzCam`.
2. Extract this project ZIP on your PC.
3. Upload the **contents** of the extracted `RilzzCam` folder to the repository root.
   Make sure `.github/workflows/android.yml` is included. If GitHub's upload page hides
   dot-folders, use Git from PowerShell instead:

   ```powershell
   cd path\to\RilzzCam
   git init
   git add .
   git commit -m "Initial RilzzCam project"
   git branch -M main
   git remote add origin https://github.com/USERNAME/RilzzCam.git
   git push -u origin main
   ```

4. Open the repository on GitHub and select **Actions**.
5. Select **Build RilzzCam Android APK** and click **Run workflow**.
   A push to `main` that changes `android/**` also triggers the workflow.
6. Wait for the job to finish with a green check.
7. Open the completed workflow run. At the bottom, download
   **RilzzCam-Android-APK** under Artifacts.
8. Extract the downloaded artifact ZIP. It contains `app-debug.apk`.
9. Copy `app-debug.apk` to your Android phone and install it. If Android asks,
   allow installation from the file manager/browser you used.

GitHub Actions builds a debug APK; it is suitable for personal testing, not a signed
Play Store release. Keep the repository private if you do not want to publish your source.
